# Política de seguridad

## Versiones cubiertas

La única versión mantenida es la rama `main`. Las versiones o commits anteriores
no reciben parches de seguridad garantizados.

## Comunicar una vulnerabilidad

No abras una incidencia pública ni incluyas detalles explotables en una discusión
pública. Usa la opción **Report a vulnerability** de la pestaña *Security* del
repositorio para enviar un informe privado a los mantenedores.

El informe debe incluir una descripción reproducible, el impacto esperado, la
versión o commit afectado y, si es posible, una prueba de concepto mínima. Se
acusará recibo en un plazo objetivo de siete días y se acordará un calendario de
corrección y divulgación responsable.

La comunicación privada de vulnerabilidades debe estar habilitada en GitHub por
el propietario del repositorio. Si la opción no está disponible, no divulgues el
detalle: contacta primero con [@Carlospromo](https://github.com/Carlospromo) para
acordar un canal privado.

## Alcance

Esta política cubre el código, los workflows de GitHub Actions y las dependencias
de este repositorio. Las fuentes oficiales externas se monitorizan por motivos de
calidad del dato, pero sus vulnerabilidades o indisponibilidades deben notificarse
también a sus respectivos operadores.
